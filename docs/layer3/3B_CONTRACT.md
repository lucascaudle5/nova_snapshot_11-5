# Layer 3b contract: the operation registry (one path for every write)

Owned by Claude. Both 3b lanes read this. It states what the write path does, in the request and response
shapes, the execution protocol and the error codes. Where it is silent, follow `docs/schema/CONVENTIONS.md`
(authoritative) and ask in your findings file; do not guess.

## Scope
**In:** a generic write operation over every payload table (`create`, `correct`, `revise`, `soft_delete`,
`restore`), idempotent retries, atomic multi-record writes, source evidence, link creation, current-marker
flips, running the layer 2 rules in the same transaction, receipts. **Out (later steps):** the erase operation
and erasure list (3c), the change feed (3c), backup and restore (3d), room-specific operations (layer 5), MCP
tools and the widget (layers 5 and 6). Nothing here is exposed as a public tool in 3b.

## Where it lives
- `LedgerDO.write(routeInput, requestInput, caller)`: **internal only**, like the other `LedgerDO` methods; the
  route must be a freshly resolved Control route. No public route accepts it in 3b.
- `caller` is **server-supplied, never from the request body**: `{ asserted_by, captured_by }` with the allowed
  values of `records.asserted_by` and `records.captured_by`. A caller cannot choose these for itself; the future
  tool layer sets them from the authenticated channel (artifact page, model, widget tap, automation).

## Request (`contract_version: "write-1"`)
```ts
interface WriteRequest {
  contract_version: 'write-1'
  client_op_id: string              // UUIDv4, generated by the caller before sending; the retry identity
  sources?: NewSource[]             // sources created by this operation, referred to by `ref`
  writes: WriteItem[]               // 1 to 50 items, applied in order, all or nothing
}
interface NewSource {               // becomes a `sources` payload row plus its envelope
  ref: string                       // local alias, unique within the request, matches /^[a-z][a-z0-9_]{0,31}$/
  medium: 'text'|'audio'|'image'|'document'|'web'|'provider_record'|'artifact'
  original_text?: string; artifact_uri?: string; extracted_text?: string
  provider?: string; external_id?: string; locator?: string
  parent_source: string | null      // a `ref` or an existing source id
}
type Cite = { source: string; role: 'report'|'observation'|'instruction'|'evidence'|'context' }
                                    // `source` is a `ref` from this request or an existing source id
interface EnvelopeInput {           // all optional; unknown stays NULL (never guessed)
  event_start_at?: string|null; event_end_at?: string|null
  time_precision?: 'instant'|'interval'|'date'|'approximate'|'unknown'
  reported_at?: string|null
  attribution_date?: string|null; time_zone?: string|null
  attribution_basis?: 'user_selected'|'source_supplied'|'derived'|'unknown'
}
type WriteItem =
  | { op: 'create'; table: string; ref?: string; fields: Record<string, unknown>; cites: Cite[]; envelope?: EnvelopeInput }
  | { op: 'correct' | 'revise'; table: string; ref?: string; target: string; fields: Record<string, unknown>
      reason: string; cites: Cite[]; envelope?: EnvelopeInput }
  | { op: 'soft_delete' | 'restore'; table: string; ref?: string; target: string; reason?: string; cites: Cite[] }
```
- `fields` are domain columns only. For `correct` and `revise` they are a **partial merge**: the new revision copies
  the target's current domain values and overrides the supplied ones (use `null` to clear an optional column).
- A field value that is a string starting with `#` followed by a `ref` is replaced by the id of the record that
  earlier item created (only allowed in columns whose descriptor has `references`). Unknown refs are an error.
- `target` is a revision id or `#ref`. It must name the **current terminal revision** of its lineage (see
  "Conflicts"). Callers may pass any revision id they once saw only through an explicit lookup tool (later); in
  3b a non-current target is `stale_predecessor`.
- **Derived values the server fills and callers may never supply:** `id`, `is_current`, `is_erased`, every envelope
  column except those in `EnvelopeInput`, `ingested_at`, `op_seq`, `client_op_id`, `change_kind`, `root_id`,
  `supersedes_id`, `deleted_at`, `asserted_by`, `captured_by`, and every **root mirror column** (descriptor
  `derived`/`rootMirrors`: the server sets `series_root_id` from `records.root_id` of the pinned id, and so on).
- Every non-`sources` write must `cite` at least one source (rule P02); the operation fails at commit otherwise.
- The registry never invents child rows. A deliberate revision of a parent that owns a child snapshot must include
  the full new child snapshot in the same request (`OPEN_QUESTIONS.md`, "How does a revised parent carry its
  children?"). Rule N01 checks the cases it can.

## Response
```ts
type WriteReply =
  | { ok: true; contract_version: 'write-1'; op_seq: number; client_op_id: string; replayed: boolean
      results: { ref: string|null; table: string; id: string; root_id: string; change_kind: string }[]
      sources: { ref: string; id: string }[] }
  | { ok: false; code: WriteErrorCode; detail?: string; violations?: { rule: string; record_id: string; detail: string }[] }
type WriteErrorCode = 'invalid_request' | 'unknown_table' | 'unknown_column' | 'invalid_value' | 'missing_required'
  | 'unknown_ref' | 'stale_predecessor' | 'not_deleted' | 'already_deleted' | 'unique_conflict' | 'reference_missing'
  | 'rule_violation' | 'digest_conflict' | 'too_large' | 'store_identity_mismatch' | 'storage_unavailable'
```
`results` follow request order, one entry per `writes` item. Replies never contain secrets or digests.

## Idempotency (retry safety)
- **Digest:** `HMAC-SHA-256(secret, "nova.write.v1\n" + canonicalJson(requestWithoutClientOpId))`, hex, stored as
  `request_digest = "hmac:v1:<hex>"`. The secret is the Worker binding `RETRY_HMAC_SECRET` (at least 32 bytes,
  base64), **never stored in the database**; a missing or short secret fails closed (`storage_unavailable`).
- **Canonical JSON:** UTF-8, keys sorted by code point, no whitespace, integers without exponent, `null` kept,
  `undefined` omitted, strings NFC-normalized is **not** applied (bytes are preserved), arrays keep order;
  numbers that are not finite are rejected. Specify and test edge cases (absent versus `null` differ).
- **Lookup first:** if `operations.client_op_id` exists: same digest returns `replayed: true` with the original
  results **and writes nothing**; a different digest returns `digest_conflict`. A replayed result list is rebuilt
  from `records WHERE op_seq = ? ORDER BY rowid` in request order (no stored id list), and `ref`s are re-attached
  from the retried request.
- An operation row is inserted **inside** the same transaction as its records; an aborted operation leaves no row,
  so the same `client_op_id` may be retried after a failure that rolled back.

## Execution protocol (one `transactionSync`)
1. Parse and size check (request at most 256 KB, 50 writes, 40 sources).
2. Digest and idempotency lookup (above).
3. Insert `operations` (`operation_kind='write'`, `retry_policy='open'`, digest, `ingested_at`), read `op_seq`.
4. Create `sources` first (record envelope `kind='sources'`, `change_kind='original'`, then payload).
5. For each write item in order:
   - **create**: new UUIDv4 `id` (crypto), `root_id = id`, `change_kind='original'`, `is_current=1`.
   - **correct** / **revise**: load the target's payload, require it to be the current terminal live revision, flip
     `records.is_current` to 0 on the target (the composite FK mirrors it to the payload), insert the successor
     (`root_id` of the target, `supersedes_id` = target, `change_kind`, required `change_reason`), `is_current=1`.
   - **soft_delete**: successor with `change_kind='delete'`, `deleted_at` = now, payload copied from the target,
     `is_current=0`. **restore**: requires the target to be a tombstone; successor with `change_kind='restore'`,
     payload copied, `deleted_at` NULL, `is_current=1`.
   - Merge `fields`, validate against the descriptor (columns exist, types, `requiredLive`, vocabulary, bounds),
     replace `#ref` values, derive root mirrors from the referenced record's `root_id`, apply the envelope.
   - Insert the `record_sources` rows for each `cite` (new `records` envelope `kind='record_sources'`, then payload).
6. Run `checkOperation(sql, op_seq)` (layer 2 rules). **Any violation rolls back the whole operation** and returns
   `rule_violation` with the violations. The rules are the single definition of cross-row correctness; do not
   re-implement them.
7. Return the receipt. Failures anywhere in steps 3 to 6 roll back everything, including the operation row.

## Conflicts
- **Stale predecessor:** target is not the current terminal live revision (already superseded, already deleted,
  erased, or not found) → `stale_predecessor` (or `already_deleted` for `soft_delete` on a tombstone, `not_deleted`
  for `restore` on a live record). Two requests racing on one lineage: the first commits, the second gets
  `stale_predecessor` (the Durable Object serializes them; the unique `supersedes_id` and the partial keys are the
  backstop).
- Database constraint failures map to codes: partial unique keys → `unique_conflict`, foreign keys →
  `reference_missing`, CHECKs → `invalid_value`. Never return raw SQLite text to a caller; put a short safe
  `detail` (column or key name only).

## Limits (Durable Object SQLite)
At most 100 bound parameters and 100 KB per statement; compound selects at most 4 terms; row size under 64 KB.
Build every INSERT from the descriptor's column list.

## What 3b must prove (gate)
Real Durable Object tests (workerd) show: a retry never double-writes (same results, same `op_seq`, no new rows);
a changed body with the same `client_op_id` conflicts; a violating write rolls back completely, for at least one
rule from each of the L, P, K, G and F groups; a correction keeps lineage and flips markers; a soft delete and
restore round trip; stale predecessors and racing writes behave as above; sources, links and cross-room writes
commit together; root mirrors are derived and a supplied mirror is rejected; a caller cannot set server-owned
columns; and the **Fitness proving case** works through the generic path with no Fitness-specific code: log a
set (an actual `body_workouts` row plus a `body_workout_sets` row), correct it, retry it, reject a stale
correction, soft delete and restore it, and read it back with a SQL query.
