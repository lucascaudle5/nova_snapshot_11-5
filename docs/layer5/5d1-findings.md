## Verbs

All six verbs require a UUIDv4 `client_op_id`, enforce the common write switch and per-tool owner rate limit, set `captured_by='model'` and `asserted_by='user'`, create report text sources from owner-supplied text, and submit one atomic registry operation. Optional `date` is a local `America/Chicago` attribution date: omitted uses today's derived date; supplied uses `user_selected`; malformed or future actual dates return `invalid_params` with `field='date'`. Planned blocks may be in the future. The target resolver uses an internal table/column allowlist, resolves prior revisions by root, ignores deleted/erased targets, and reuses the target recorded by an existing `client_op_id` on retry.

| Verb | Inputs and stored form | Allowed values / important errors |
|---|---|---|
| `focus.start_session` | `intention`, optional `reason`, `intended_result`, `subject_id`, `planned_block_id`, `configuration`, `planned_seconds`, required `said`, optional `date`; creates a `started` `focus_sessions` row and sourced `start` event atomically. | Session status schema: `planned`, `started`, `paused`, `ended`, `not_done`, `abandoned`, `unknown`. `subject_not_found`, `ambiguous_subject`, `configuration_not_found`, `ambiguous_configuration`, `planned_block_not_found`, `ambiguous_planned_block`. |
| `focus.log_checkpoint` | `session_id`, any nonempty subset of `done`, `happened`, `unresolved`, `next`, optional `date`; one sourced event per supplied part. Omitted parts are absent. | Maps to existing event kinds: `done` → `progress`, `happened` → `self_report`, `unresolved` → `obstacle`, `next` → `checkpoint` and `next_action`. Session target errors `session_not_found`, `ambiguous_session`. |
| `focus.end_session` | `session_id`, `outcome`, required `said`, optional `reason` and `date`; corrects one current session row. The owner text/reason is cited; reason is not forced into `reason_text`, whose schema only permits `not_done`/`abandoned`. | Outcome is one of `ended`, `not_done`, `abandoned`, `unknown`; session target errors as above. |
| `learning.log_practice_attempt` | `practice_item_id`, `response_text`, `status`, optional `ink_document_id` and `date`; response text is the cited owner source. | Status: `started`, `partial`, `completed`, `abandoned`, `unknown`. `practice_item_not_found`, `ambiguous_practice_item`, `ink_document_not_found`, `ambiguous_ink_document`. Existing DDL requires response/Ink/artifact evidence for `partial` and `completed`. |
| `learning.log_help_request` | `subject_id`, `mode`, `request_text`, optional `date`; creates `learning_help` with status `requested` and a text source. The Worker does not answer. | Mode: `hint`, `explanation`, `question`, `worked_example`, `full_solution`, `discussion`. `subject_not_found`, `ambiguous_subject`. |
| `music.log_interpretation` | track id or exact case-insensitive title, `interpretation`, optional `date`; creates an `annotations` row with category `interpretation` and status `explored`, asserted by `user`. | `track_not_found`, `ambiguous_track`. |

All verbs may also return `invalid_params` (with a `field` hint), `writes_disabled`, `rate_limited`, `storage_unavailable`, or registry errors including `digest_conflict`. No schema changes, changes to existing view columns, `server.ts` edits, deploys, pushes, or artifact changes were made. `server.ts` did not need changes.

## Review corrections (Claude, 2026-11-05)

The Workers suite could not run in the lane's sandbox, so these were found by running it:
- **Retries broke on a server clock.** Five of the six verbs put `new Date().toISOString()` inside the registry request, so a retry with the same `client_op_id` built a different body and got `digest_conflict` instead of the replayed receipt. The server no longer stamps a time. `focus.start_session` and `focus.log_checkpoint` accept an optional `event_time` (ISO with offset, never in the future); the page should set it once per intent and freeze it with the request. Without it the event has an attribution date only and its time stays unknown (NULL). The other four verbs carry the attribution date only.
- **`focus.end_session` retry resolved the wrong revision.** The retry lookup returned the new session revision instead of the one originally targeted, again giving `digest_conflict`. The resolver now follows `supersedes_id` for a session correction.
- **A test used a different owner's empty store** for its rate-limit case; it now expects `track_not_found` first and `rate_limited` second.
- Reverted a lane workaround in `scripts/build-widget.ts` (`configLoader: 'runner'`) that is not needed on this machine.
